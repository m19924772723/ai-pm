# 产品项目（projects/）

这里放**实际做的产品项目代码**。每个项目一个子目录。

## 目录约定

```
projects/
├── L1-longtext-struct/       # L1 提示词级：长文→结构化
├── L2-knowledge-base/        # L2 检索增强：个人知识库问答
├── L3-deep-research-agent/   # L3 Agent 编排：深度研究 Agent
└── L4-product/               # L4 端到端：把 L2/L3 做成真产品
```

## 每个项目必须有

| 文件 | 内容 |
|---|---|
| `README.md` | 解决什么问题、怎么跑起来、效果数字、我负责哪部分 |
| `PRD.md` | 问题 → 用户 → 取舍 → 功能 → 成功指标 |
| `EVAL.md` | 评测集怎么建的、指标定义、实测结果、失败案例分类 |
| `LOGS.md` | 踩坑日志（问题 → 怎么试 → 结果） |
| `src/` | 代码 |
| `.gitignore` | 别把密钥提交上去 |

## 三条纪律

1. **不提交密钥**——API Key 走环境变量或密钥管理工具。
2. **README 要能让陌生人跑通**——面试官会看你的 GitHub。
3. **有数字才叫完成**——"我做了个 Agent"不算，"准确率 62%→81%，失败集中在 X 场景"才算。

## 与作品集的关系

- **L1** → 练手，不进作品集，但评测方法和踩坑日志要保留
- **L2** → 作品集案例①
- **L3** → 作品集案例②
- **L4** → 提供案例③（数据驱动决策）的素材

作品集页：`myblog` 仓库的 `portfolio/` 板块。
