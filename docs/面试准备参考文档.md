## 一、通用练习方法（先看这个）

### 三个必须遵守的原则

**1. 开口练，不要只在脑子里想。**

面试是口语表达考试，不是知识考试。想清楚 ≠ 说清楚。**每次都录音**，回放时你会发现自己大量"嗯""然后""就是"的填充词，以及逻辑断层。

**2. 一次只练一个题型，不要混。**

六段式、费米、数据分析是三种完全不同的肌肉。同一周混练三种，每种都练不熟。

**3. 练完立刻复盘，写下三个问题。**

复盘模板（就三行）：
```
这道题我哪一步卡住了？
面试官会追问什么，我答得上吗？
下次要改的一个具体动作是什么？
```

### 判断自己练到位了没有

| 层次 | 表现 |
|---|---|
| 不合格 | 听完题就开始讲功能点，没有分群、没有取舍 |
| 及格 | 有结构，但结构是背的，被追问就乱 |
| **合格** | 知道自己在哪一步，被追问能现场调整结构 |
| 优秀 | 主动收窄范围，主动说"我放弃了 X，因为 Y"，主动收尾总结 |

> **目标定在"合格"**，这是校招通过线。优秀是工作两三年后的事。

### 用 AI 当陪练（本工作区已具备）

| 练什么 | 怎么用 |
|---|---|
| 产品设计题 | 说"用 product-sense-interview-answer 陪我练这道题：如何改进 XX" |
| 费米估算 | 说"出 3 道大厂费米估算题，我答完你逐条指出漏洞" |
| 模拟面试 | 让 AI 扮演面试官，按你简历逐条深挖，**要求它追问三层** |
| 群面 | 让 AI 扮演同场竞争者，模拟资源分配类题目 |

**关键**：让 AI **挑错**，不是让 AI 给答案。给答案没有练习价值。

## 二、产品设计题：六段式框架

> 适用：「如何改进 X」「为 Y 人群设计一个产品」「X 的下一个功能是什么」
> 来源：`product-sense-interview-answer` 技能

### 核心原则：绝不要从功能开始

面试官真正在考的是六件事：

1. 能不能澄清模糊的题目，而不是卡住
2. 能不能把用户价值和商业逻辑挂上
3. 会不会**分群**（而不是说"所有人"）
4. 能不能**只挑一个**痛点（而不是列十个）
5. 会不会把 MVP 的取舍讲明白
6. 时间压力下表达是否清晰

### 六段式（顺序不能换）

| 段 | 名称 | 要做什么 | 质量线 |
|---|---|---|---|
| 1 | **澄清** | 问 1–2 个最关键的问题，收窄范围；面试官不答就自己**说明假设**然后往下走 | 问"面向观看者、创作者还是广告主"，而不是"移动端还是桌面端" |
| 2 | **价值理由** | 为什么这件事现在重要：市场大不大、对真实的人意味着什么、为什么是现在 | **别编数字**。定性判断好过假精确。结尾给一句论点（thesis），让后面显得顺理成章 |
| 3 | **产品目标** | 一句话：`帮助[谁][达成什么]，从而是[更大的影响]` | 目标是**用户结果**，不是功能。反例："做一个个性化 AI 学习路径功能"是伪装成目标的功能 |
| 4 | **分群选目标** | 先分清生态里的角色，再选你要服务的那个；然后用**两个真正改变需求的维度**分群 | 好的维度：任务/目标、代价高低、专业程度、使用频率。**弱的维度**：与产品无关的人口统计切分 |
| 5 | **痛点排序** | 把用户旅程拆成 4–6 段，列出摩擦点，按**频次 × 严重度**挑出最该先解决的那一个 | 痛点必须是**用户摩擦**，不能是"缺某功能"。"看完一个视频后没有结构化的进阶"是痛点；"没有 AI 学习路径"已经是方案了 |
| 6 | **方案与取舍** | 列 **3 个本质不同**的方案 → 对比（用户影响 / 成本）→ 选定 1 个 MVP + **明确说出 v1 不做什么** → 一句话收尾 | 三个方案要换**机制**，不能是同一个想法的三种包装。收尾句要复述：目标人群 + 核心痛点 + 第一个下注 |

### 反模式（这些会让你直接挂）

| 反模式 | 为什么致命 |
|---|---|
| 功能堆砌 | 没说清给谁解决什么问题就抛点子 |
| 分群表演 | 列一堆分群，选哪个没有权衡逻辑 |
| 目标是功能 | "做一个 XX 功能"不是目标 |
| 假痛点 | "用户需要一个看板"——这是方案不是痛点 |
| 三个假选项 | 三个方案其实是一个方案 |
| 收尾无力 | 列完功能就结束，没有一句话总结 |
| 每个分支都答 | 想证明广度，但产品面试奖励**聚焦** |

### 范例

**「如何改进 YouTube？」（面向初级学习者）**

- **澄清**：优化对象是观看者、创作者还是广告主？→ 假设是**观看者**
- **价值理由**：学习类内容量大但"看完就忘"；平台目前优化的是时长，不是学习效果
- **产品目标**：帮助初级学习者找到"看完不后悔"的内容，从而让平台成为有意图的学习目的地
- **分群**：按**学习意图 × 专业程度**分。选"有明确学习目标但零基础的观看者"
- **痛点**：旅程拆 5 段（找 → 选 → 看 → 看完 → 下一步）。最高频且最严重的摩擦是**看完一个视频后没有结构化的下一步**
- **方案**：① 学习路径 ② 看完后自动生成知识图谱 ③ 学习小组互助。选 **①学习路径**为 MVP，v1 明确不做"进度社交分享"。收尾：*"我选零基础但有明确目标的观看者，先解决'看完没有下一步'这个最高频痛点，第一个下注是学习路径。"*

### 常见坑

- **跳过澄清直接答** → 答得再漂亮也可能偏题
- **忘了商业/公司视角** → 只谈用户体验，面试官会认为你不懂业务
- **不会收尾** → 面试官记不住你的答案

## 三、费米估算题：四步拆解法

> 适用：「北京有多少家咖啡店」「某功能一年能带来多少 GMV」「深圳有多少个产品经理」
> 本质：**把未知问题逐步拆解成已知问题**

### 四步

| 步 | 动作 |
|---|---|
| 1 | **明确问题**——问清统计口径（谁？什么行为？算哪些收入？） |
| 2 | **判断切入角度**——需求端 or 供给端（这两个角度能解决 80% 的问题） |
| 3 | **拆解列公式**——按 **MECE**（不重不漏）层层拆 |
| 4 | **计算**——给每个元素赋有依据的数值 |

### 两条铁律（最容易犯错的地方）

**铁律 1：不要把一个未知数拆成另一个未知数。**

反例：估算"杭州一家奶茶店一天卖多少杯"→ 用"杭州有 1000 家奶茶店"去除。但"杭州有多少家奶茶店"**本身也是未知数**，等于用一个未知数推另一个未知数，逻辑上是空的。

**解法**：继续拆，直到每个元素都是**已知数据或生活常识**。

**铁律 2：赋值不能偏离真实范围。**

费米估"芝加哥每户 4 人"有依据；你估"每户 10 人"就是拍脑袋。所有数值都要有数据或经验支撑。

**为什么允许估算**：你不是只估一次，而是一串估算——有的偏高有的偏低，相乘后**相互抵消**，回归到较准的平均值（平均律）。

### 完整案例：杭州每年的奶茶店市场规模

**① 明确问题**
- "规模"指什么？→ 销售额
- 只算奶茶还是含其他？→ 所有饮品，不含面包类食品

**② 判断角度**
这是地域市场规模，杭州常住人口是**可知数字** → 从**需求端**切入

**③ 拆解列公式**
```
杭州奶茶店年规模 = 常住人口 × 渗透率 × 年购买频次 × 客单价
```
再按 MECE 细分人群（小孩 / 年轻人 / 中年人 / 老年人）——因为不同年龄段的渗透率和频次差别很大，分开算再相加更准。

**④ 计算**
- 常住人口 ≈ 1000 万（**已知常识**）
- 渗透率 ≈ 需要估 → **用样本估**："我随机问 100 个朋友，其中 N 个喝奶茶"
- 年购买频次、客单价 → 同样用样本或生活经验

### 两个必须避开的回答

1. **"可以百度查一下"** —— 直接出局。这类题考的是分析方法，不是数据检索。
2. **死磕某个数字的准确性** —— 面试官要的是拆解逻辑和边界考虑，**答案本身不重要**。

### 常见坑

- 忘了先明确口径，直接开始算
- 拆解后的元素还是未知数
- 赋值离谱（把一个 100 万人口城市说成有 50 万家店）
- 不做 MECE 分群，导致明显低估或重复计算

## 四、数据分析题：三步框架

> 适用：「某 App DAU 突然下降 10%，怎么排查」「新用户留存下降怎么定位」
> 框架：**看数据 → 做拆分 → 做假设**

### 第一步：看数据——先确认这波动是不是真的异常

不是所有下降都是问题。波动分**正常**和**异常**，按持续时间分**暂时性 / 周期性 / 持续性**。

要做的事：
- 和产品、运营、研发、运维**确认数据真实性**（可能是统计出错）
- 看波动**持续多久**
- 对比**同比 / 环比**，判断幅度是否在合理范围

这一步可能直接查出的原因：服务器异常、后台统计出错、报表错误、**指标计算口径不一致**、外部恶意行为。

> 一句话：**先排除"问题不是问题"和"数据本身是错的"。**

### 第二步：做拆分——缩小排查范围

**⚠️ 必须警惕「辛普森悖论」**：整体分析和分部分析可能得出**相反**的结论。

**① 从指标上拆**（按指标树，由粗到细）

```
DAU = 新用户 + 老用户留存 + 流失用户回流
```
- 新用户 → 有来源渠道
- 老用户 → 有留存渠道
- 回流用户 → 自然回流 / 干预回流
- 共同维度：软件版本、地区、设备、活跃时段

复合指标要用乘式拆：
```
GMV = 新用户 × 转化率 × 新用户客单价 + 老用户 × 转化率 × 老用户客单价
```

**② 从业务流程上拆**

用户从注册 → 进首页 → 留存/流失，任意一步都可能是指标下降的元凶。
（例：新用户首次进首页，看到不喜欢的推荐内容直接卸载 → 锅在推荐系统的冷启动）

**③ 内因 vs 外因**

| | 范围 | 例子 |
|---|---|---|
| **内因** | 用户、产品、运营、内容质量 | 版本 bug、策略调整、内容质量下滑 |
| **外因** | 政治、经济、法律、竞品、宏观 | 政策发布、竞品动作、节假日 |

**经验法则**：
- **短期变化找内因**
- **长期异动找外因**
- 外因可用 **PEST** 做宏观分析
- 在数据上关注指标的**起点、拐点、终点**

**辅助思考的五个问句**：
1. 指标构成是什么？
2. 业务流程是什么？
3. 是否有外部因素？
4. 相关因素有哪些？
5. 有没有注意辛普森悖论？

### 第三步：做假设——验证

先从理论和经验上提出各种假设，再通过实验验证，相当于给拆解出的"树"做**剪枝**。

- **可稳定重现的问题** → 用 **AB 实验**验证
- **不能稳定重现的问题** → 用业务经验缩小范围，或做相关分析
- **特殊情况**（如发现大量脚本假用户）→ 挖已有日志（IP、设备标识）

> 注意：真实环境中存在许多变量（产品迭代、运营策略变更、线上还有别的 AB 实验在跑），会干扰结论，验证方案要因情况设计。

### 答题示例（"DAU 下降 10%"）

> "我先分三步：**看数据、做拆分、做假设**。
> 第一步看数据：先确认口径有没有变、是不是统计故障，再看同比环比，判断这 10% 是不是真的异常。
> 第二步做拆分：按 `DAU = 新用户 + 老用户留存 + 回流`拆开，再按渠道、版本、地区、设备下钻——这里要小心辛普森悖论，整体跌但分端可能只有一端跌。同时按业务流程看哪一步漏斗掉了。内因看产品和运营，外因看竞品和节假日。
> 第三步做假设：把最可疑的因子提出来，可重现的用 AB 实验验证，不可重现的用日志下钻。
> 最后给出监控动作。"

## 五、AI 产品特有题

> 这是你**最该拿满分的部分**——因为你有真实项目。别人只能空谈概念。

### 高频题与答法要点

| 题目 | 答法要点 |
|---|---|
| **你怎么看 AI Agent 的落地现状？** | 分三层说：**能力边界**（能稳定做什么）、**典型场景**（什么场景已跑通）、**卡点**（可靠性、评测方法、成本）。**必须举你项目里的具体例子** |
| **你常用的模型有哪些？差别在哪？** | 说清你在项目里**怎么选型、为什么换、换完效果差多少**。泛泛谈模型好坏 = 没真做过 |
| **一个 AI 功能效果不好，怎么排查？** | 按链拆：**输入质量 → 检索/上下文 → 提示词 → 模型选择 → 评测方法**。举例：你在项目里踩过的具体坑 |
| **AI 是不是必要的？** | 必答的一题。说清"非 AI 方案（规则匹配）为什么不行"——例如"用户问法开放多样，规则维护成本随时间上升" |
| **怎么评测 AI 效果？** | 建**评测集**（20–50 条代表性样本）+ 定义指标（准确率/召回/人工打分）+ 记录失败案例分类。**这是拉开差距的地方** |
| **幻觉怎么处理？** | 分层：检索增强、输出约束、置信度提示、人工兜底。别只说"加个提示词" |

### 你的差异化打法

面试官一定会问"你具体做了什么"。你要能讲：

1. **为什么选这个方向**（不是"我想练手"，而是"访谈后发现这个痛点最高频"）
2. **为什么这么设计**（取舍记录——被砍的方案和理由）
3. **效果数字**（62% → 81%，失败集中在超长文档场景）
4. **踩过的坑**（这里最能证明你真的做过）
5. **如果重做会改什么**（体现反思深度）

> **"会用 AI"和"懂 AI"在招聘里是两个量级。** 你不只要说用过什么工具，要说清"底层卡在哪、你怎么绕过/解决"。

## 六、简历深挖与行为面

### 简历深挖：面试官只查三件事

| 追问 | 你要准备的 |
|---|---|
| 这个数据怎么来的？ | 采集方式、样本量、**局限**（不夸大） |
| 为什么这么做？有别的做法吗？ | 取舍记录 + 被砍方案的理由 |
| 你具体负责哪部分？ | **明确划界**："X 是我做的，Y 是现成的" |

⚠️ **实验室项目的典型崩塌链**（27 届硕士的真实经历）：
> 文档怎么切 → 为什么这么切 → 召回效果怎么评估 → 不同方案的数据对比 → 有没有上线、谁在用、你负责哪部分

**答到第三层就崩**，因为实验室项目没经历过上线后才有的问题。

**解法**：你的第一个项目**必须有真实用户 + 实测数据**，这样这条链每一层都有答案。

### 行为面：STAR

```
S 情境：什么背景、什么约束
T 任务：你要解决什么、目标是什么
A 行动：你具体做了什么（重点，占一半篇幅）
R 结果：数字化的结果
+ 反思：如果重做我会改什么
```

**准备清单**（研一上结束前攒够）：
- [ ] 一个最有成就感的项目
- [ ] 一次意见冲突的解决过程
- [ ] 一次失败经历
- [ ] 为什么想做产品经理（1 分钟版 + 3 分钟版）

**注意**：
- 结尾的"反思"是加分项，多数候选人不准备
- 冲突题重点讲**你怎么用数据/用户证据说服对方**，而不是"我们关系好"
- 动机题要用**具体事件**，不要"我热爱产品"

### 自我介绍

准备两个版本：
- **1 分钟版**：学校专业 + 一个最亮的项目 + 求职方向
- **3 分钟版**：上面 + 一段实习 + 为什么是 AI 产品方向

**别背稿**，但要练到不卡壳。

## 七、群面（无领导小组讨论）

### 考察什么

沟通、推动、结构化思考、临场应变。**随机性强，比结构化面试更难装。**

### 关键认知

**不必抢 leader，也不必做最强势的那个。** 有效的角色是：

| 角色 | 做什么 | 适合谁 |
|---|---|---|
| **时间管理者** | 掌控节奏，提醒"还剩 5 分钟，我们该收敛了" | 稳，不容易出错 |
| **观点整合者** | 把大家的散点汇总成结构，推进到下一步 | 想突出，风险中等 |
| **结构化总结者** | 最后做清晰收尾陈述 | 表达好的人 |

**最危险的是"抢了 leader 但压不住"**——会被判定为不成熟。

### 操作要点

- **自我介绍**控制在 1 分钟左右，加个人特色但别用力过猛
- 发言**推动进程**，而不是重复别人观点
- **不要否定别人的人**，否定**观点**并给替代方案
- 讨论顺利时按方法技巧挑好角色；出现争论时做**收敛**而不是加压
- **最后一定要有结构化总结**（常被指定，也是加分点）

### 常见题型

- 资源分配（有限预算怎么分）
- 产品方案（选哪个方向）
- 排序题（哪些功能优先做）
- 开放讨论（如何提升 XX）

### 怎么练

找 4–6 个同学，线上或线下模拟 1 次（30 分钟 + 15 分钟复盘）。研一上练 2 次就够，研二下密集练。

## 八、练习节奏（18 周排期）

**原则：三轨并行，每周固定 3–4 小时。** 项目线是主线，面试线是"把项目练成口头表达"。

| 周 | 面试线任务 |
|---|---|
| 1 | 建题库（收集 20 道大厂真题） |
| 2 | 产品设计题 3 道（`product-sense-interview-answer`） |
| 3 | 费米估算 3 道 |
| 4 | 费米 3 道 + 复听上周录音找问题 |
| 5 | 数据分析题 3 道 |
| 6 | 数据分析 3 道 + 完整模拟 1 次 |
| 7 | 从项目挖 2 个 STAR 故事 |
| 8 | 再挖 2 个 STAR 故事（共 4 个） |
| 9 | 学群面规则 + 同学模拟 1 次 |
| 10 | 群面模拟再 1 次 + 复盘 |
| 11 | 拿简历问自己 20 个深挖问题并作答 |
| 12 | 产品设计题 3 道（限时 25 分钟） |
| 13 | **拿实测数据做 1 次完整模拟面试** |
| 14 | 写 1 分钟与 3 分钟自我介绍 |
| 15 | 找有实习的学长做 1 次模拟面试 |
| 16 | 简历 + 面试完整串联演练 1 次 |
| 17 | 复盘全部录音，列出薄弱题型 |
| 18 | 把薄弱题型排进研一下计划 |

**每周固定动作**：练习后**必须录音**，回放一次，写在"周复盘日志"sheet 里。

## 九、参考资源

### 必备方法论

| 书 | 用途 |
|---|---|
| 《Decode and Conquer》Lewis C. Lin | 产品面试经典，六段式框架的出处之一 |
| 《Cracking the PM Interview》 | PM 面试系统指南 |
| 《俞军产品方法论》 | **你已买**。判断"值不值得做"的第一把尺子 |

### 社区与题库

- **人人都是产品经理**（woshipm.com）—— 费米估算、DAU 分析等框架的公开来源，每周精读 2 篇
- **牛客网** —— 大厂真题、面经（"产品经理面试问题合集"类帖）
- **知乎** —— 无领导小组讨论攻略、费米问题案例
- **OfferStar / 应届生求职网** —— 校招信息与进度
- **Lenny's Newsletter** —— AI PM 最前沿（英文，免费部分够用）

### 本工作区可用技能

| 需求 | 技能 |
|---|---|
| 产品设计题陪练 | `product-sense-interview-answer` |
| 市场规模/估算 | `tam-sam-som-calculator` |
| 项目复盘、写 PRD | `epic-hypothesis`、`prd-development` |
| 公司/行业研究（面试前做功课） | `company-intel`、`company-research` |
| 竞品作战卡 | `battle-card-builder` |
| 需求该不该做（高频题） | `feature-investment-advisor`、`prioritization-advisor` |
| 入职后前 90 天 | `executive-onboarding-playbook` |

### 三条最重要的提醒

1. **面试准备不能脱离项目。** 没有项目，所有框架都是空的；有项目，框架才有素材可填。
2. **开口练 + 录音复盘**，这是唯一有效的练习方式。
3. **被拒不代表你不优秀，只是不匹配。** 有 26 届硕士被字节挂了 5 次，最后照样拿到 offer。
