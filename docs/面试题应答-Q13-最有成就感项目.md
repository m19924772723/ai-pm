## STAR 正文（口述版）

**S 情境**：我要给「AI 产品经理个人知识库答疑」做一个案例级作品——把工作区 48 篇真实文档（笔记/复盘/项目文档）做成 RAG 问答系统，且每个回答必须能引用原文出处。这不是 demo，验收标准是「八问八答都有数字证据」。

**T 任务**：系统要过四条硬指标：召回率、检索相关性、引用准确率、拒答正确率。我全程独立完成：语料工程、索引、问答链路、评测集、失败排查。

**A 动作**（按时间线）：
1. 先建 30 条评测集（含 10 条无答案的拒答样本），gold 人工标注——**先有尺子再调系统**；
2. 发现纯向量检索在中文同域语料上整体不可用（Recall@5 = 0/10）→ 改混合检索（稠密 + 中文二元组 BM25 + RRF 融合），召回拉到 90%；
3. 上下文相关性卡在 30% → 穷举 5 种排名型重排方案（扩池/调权重/doc 级聚合/分数融合/PRF），天花板 ≈45% → 判断必须换真正的相关性打分器 → 本地部署 110M cross-encoder（bce-reranker-base_v1，CPU fp16，零 API 成本）→ 相关性和 MRR 显著提升；
4. 修三个「症状像 bug 实际是设计问题」的坑：索引过期（语料每天变）、Chroma 两次 get 顺序不一致、gold 标窄冤枉系统——**每一次都先归因再动手**；
5. 引用校验做成「quote 必须是块文本连续子串」（复用 L1 的证据规则），校验通过才输出，回答带 doc_id + 字符偏移，界面可高亮原文。

**R 结果**（2026-10-15 口径，全部脚本产出）：
| 指标 | 结果 |
|---|---|
| 召回率 Recall@5 | **100%**（20/20），从 90% 提升 |
| MRR | **0.713**（0.552 → 0.713） |
| 上下文相关性（P@5） | **55%**（30% → 55%，Rerank 引入） |
| 引用准确率 | **100%**（20/20） |
| 拒答正确率 | **100%**（10/10） |
| 单测 | 44 条（含检索回归测试 3 条） |

**如果重做我会改什么**：① gold 标注不手稿冲刺，直接用试用反馈驱动转正式（当前还是 draft_manual）；② 55% 差 5pp 目标，根因是同义改写题（查词面检索失效）与命令题（词面兜底弱）——应该在评测集设计阶段就补这两类样本，而不是上线后才定位；③ 早扩评测集：10 条草案时看着 90%，扩到 30 条立刻现形，小样本会骗人。

## 为什么选这个故事（对齐 8 证据框架）

- **解决谁的问题**：我自己（PM 求职作品集）+ 未来任何「私域资料答疑」场景的用户；候选点评对象也可直接用。
- **AI 是否必要**：语义匹配、跨文档综合只能靠 LLM；但引用溯源是产品约束不是模型能力——能分清「模型能做」和「产品要管」是加分点。
- **效果怎么衡量**：五指标评测集，口径公开。
- **失败怎么排查**：三个真坑 + 根因链（30% → 排名型天花板 → cross-encoder），每一步有前后对比。
- **谁在用 / 你负责哪部分**：诚实口径——**还没有真实用户**（试用材料已备好，见 `docs/L2-1试用材料.md`）；代码、评测、排查全是我独立完成。
