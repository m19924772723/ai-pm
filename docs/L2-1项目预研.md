# L2-1 项目预研：个人知识库问答（RAG）

> 预研日期：2026-10-07（Day 15）　·　**这是第一个正式作品集案例**
> 周期：3–4 周（第 5–8 周）　·　定位：从"提示词级"上到"检索增强级"
> 状态：预研完成，待 L1 部署上线后开工

---

## 1. 一句话定义

**上传自己的资料（论文/笔记/文档），用自然语言提问，答案精确引用到原文段落，答不出时明确说"资料里没有"。**

## 2. 目标用户与场景

| 项 | 内容 |
|---|---|
| 用户 | 需要查自己资料的人：研究生（文献/课程笔记）、职场新人（规范/文档） |
| 场景 | ①"我记得看过这个，在哪？" ②"这几份资料里关于 X 怎么说？" ③"我要写东西，需要准确引用" |
| 现状 | 全文搜索只能命中关键词；今天用 AI 聊又怕它编；找一句话要翻半小时 |
| 目标 | 提问 5 秒内得到答案 + 可点击的原文出处；答不出明确说不知道 |

## 3. 为什么必须用 AI（面试必答，先想清楚）

1. **关键词检索命中率低**：资料是非结构化的，用户问"那个关于迁移成本的说法"——关键词搜不到，只有语义检索能命中。
2. **引用可信度必须靠模型判断**：哪一段真正回答了问题、哪一段只是提到了词，规则判不了。
3. **"答不出就说不知道"需要模型自评**：检索为空或证据不足时要主动拒答，这依赖模型对证据充分性的判断。

> ⚠️ 反面示例（会被面试官打回）：如果只是"把所有资料喂给长上下文模型"，那没有检索环节，也讲不出检索质量指标——**必须做检索，因为核心能力是"从大量资料里精确定位"**。

## 4. MVP 功能（3 个，必须做完）

| # | 功能 | 说明 |
|---|---|---|
| 1 | **上传与索引** | 支持 PDF / Markdown / txt；分块后建立向量索引；显示索引状态与块数 |
| 2 | **问答** | 提问 → 检索 Top-K → 生成答案；答案中的每句话标注来源块编号 |
| 3 | **引用定位 + 拒答** | 点击引用跳转到原文段落（高亮）；证据不足时输出"资料里没有找到相关内容"，不许硬答 |

### 明确不做（写进作品集，这是加分项）

- ❌ 不做多用户/权限体系
- ❌ 不做云端同步
- ❌ 不做多模态（图片/表格理解）
- ❌ 不做知识图谱/图检索
- ❌ 不做微调（用现成 embedding + LLM）
- ❌ 不做扫描件 OCR（沿用 L1 的边界）

## 5. 技术选型与取舍

| 层 | 选择 | 为什么不选另一种 |
|---|---|---|
| 向量库 | **Chroma**（本地持久化） | FAISS 更快但需自己管元数据与持久化；L2 数据量小，Chroma 的开发效率更值钱 |
| 分块 | **按标题层级 + 固定长度兜底**（512 字，重叠 64） | 纯固定长度会切断语义；纯按标题又会让单块过长 |
| Embedding | 先用**中转 API 的 embedding 模型** | 本地 bge 系列要装模型+显存；先验证链路，成本敏感再换 |
| 生成模型 | 复用 L1 的跨端点故障转移（stepfun/deepseek） | 不重写模型层，直接复用 `utils/llm.py` 的候选与兜底机制 |
| 界面 | Streamlit（复用） | 一致的技术栈，2 周内出可用 demo |
| 引用定位 | 块内字符偏移 + 原文高亮 | 只给"文档名"不够——面试验证"精确引用"必须到段落 |
| 存储 | SQLite（文档 + 块 + 向量 id） | 比 JSON 更适合做"块-文档"关联查询 |

> 一条纪律（沿用 L1）：**用现成的，不自己训模型**。

## 6. 评测设计（L1 方法 + 检索侧新增）

### 复用 L1 的三指标

格式合规率、要点覆盖率、幻觉率 —— 脚本结构、匹配器、rescore 全部复用（见 `docs/L1评测方法.md`）。

### L2 新增：检索侧指标（这是 L1 没有的环节）

| 指标 | 算法 | 目标 |
|---|---|---|
| **召回率** | 人工标注"该问题的正确来源块" → 检索 Top-K 是否包含它 | ≥ 90% |
| **上下文相关性** | 检索到的 K 个块里，真正相关的比例 | ≥ 60% |
| **引用准确率** | 答案引用的块是否真的支持该句 | ≥ 95% |
| **拒答正确率** | 资料里确实没有时，是否正确拒答（用 10 条"无答案"问题测） | ≥ 90% |

### 评测集

- 30 条问答对（问题 + 正确答案 + 正确来源块 + 类型标签）
- 其中含 **10 条故意无答案**的问题（测拒答）
- 语料：自己的真实资料（课程笔记/论文/规范）——**必须是真资料，不能是玩具数据**

## 7. 与 L1 的衔接（资产复用清单）

| L1 资产 | L2 用法 |
|---|---|
| `utils/schema.py`（JSON 提取/Schema 校验/证据回溯） | 直接复用，证据回溯升级为"引用块 id 校验" |
| `utils/llm.py`（多端点 + 故障转移） | 直接复用；新增 embedding 调用 |
| `run_eval.py` / `rescore.py` | 加检索指标，其余结构不动 |
| 评测方法文档（四类失败框架） | 直接套用 |
| 证据约束思路 | 升级：从"逐字子串"到"块 id + 段落偏移" |

## 8. 排期（3–4 周）

| 周 | 任务 | 交付 |
|---|---|---|
| 第 1 周 | 环境 + 语料整理 + 分块 + 索引跑通 | 能问一个问题并返回相关块 |
| 第 2 周 | 问答 + 引用定位 + 拒答 | MVP 三项功能可用 |
| 第 3 周 | 建 30 条评测集 + 跑 4 个指标 + 失败分类 | 第一版数字 |
| 第 4 周 | 针对性优化（分块/检索参数/提示词）+ 前后对比 + 项目说明 | 案例①成稿 |

## 9. 风险与止损

| 风险 | 信号 | 止损 |
|---|---|---|
| 检索质量差 | 召回率 < 60% | 先换分块策略（标题层级）再考虑换 embedding |
| 引用定位不准 | 引用高亮错段落 | 退化为"定位到块"（不追求精确字符偏移） |
| 拒答不准 | 该拒答时硬答 | 加"证据不足"的显式判定步骤（检索分数阈值 + 让模型自评） |
| 工期超 | 第 3 周还没 MVP | 砍成"单文档问答"（先不做批量上传） |
| 评测集造假风险 | 用玩具数据测 | **必须用自己真实资料**，否则面试讲不出场景 |

## 10. 面试怎么讲这个项目（预告）

- 解决谁的问题：研究生/职场新人查自己资料慢且不可信
- 为什么必须 AI：语义检索 + 引用可信 + 主动拒答，规则做不到
- 效果怎么衡量：4 个指标（召回率/相关性/引用准确率/拒答正确率）+ L1 的三指标
- 失败怎么排查：检索问题 vs 生成问题 vs 分块问题，分层定位（沿用 L1 的分类框架）
- 谁在用：**必须找 3-5 个同学真实试用**（L1 的教训：没有真实用户，第 7 问答不上）
