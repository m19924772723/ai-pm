## 三、数字轨迹（可讲"可度量迭代"）

```
首轮       格式合规 90%   覆盖率 67.1%   幻觉率 1.05%
修复后     格式合规 95%   覆盖率 90.8%   幻觉率 1.05%
```

归因拆解（重要）：
- 覆盖率 **+11pp** 来自修**测量工具**（匹配器两个 bug）——数字变好看，产品没变
- 覆盖率 **+7pp** 来自修**提示词真问题**（英文缺字段/语言随机）——产品真的变好
- 幻觉率**没动**：因为它是严格口径（一条证据跳句违规被如实抓出）

> 结论：**能拆开这两个来源，比一个总数字更有说服力。**

## 四、踩坑清单（5 条，都能讲"怎么排查"）

1. JSON 解析失败 → 根因是 max_tokens 被推理 token 吃掉（不是模型不会写 JSON）
2. 覆盖率 15% → 先怀疑测量工具，果然是逐字匹配器太严
3. evidence "找不到" → 分类为改写/删节/拼接三种弱引用，都不是幻觉
4. 一整批调用全失败 → 依赖故障（siyu 订阅失效），不是代码
5. 英文样本覆盖率全 0 → 匹配器只收中文二元组 + 归一化丢单词边界（两个 bug 叠一起）

## 五、做得不好的地方（诚实部分）

1. **评测集 gold 仍是草稿**（`draft_manual`），没有人工复核就用了三轮——数字只能当趋势
2. **没有真实用户**：全部自测，面试验证第 7 问（谁在用）目前答不上
3. **分块策略没做**：超长文本直接截断（4.2 万字那条），会丢后半部分信息
4. **匹配器仍是字面级**：同义改写识别不了，覆盖率被系统性低估
5. 没有 prompt 版本管理：改提示词靠改代码 + git，没有 A/B 版本号（L2 要考虑）

## 六、下一步（L2 的输入）
