## 一、三个指标：定义、算法、已知限界

| 指标 | 算法 | 分母 | 已知限界 |
|---|---|---|---|
| **格式合规率** | JSON 一次解析成功 **且** Schema 校验通过的样本数 ÷ 全部样本 | 样本数 | 无（这是硬判定，最可信的指标） |
| **要点覆盖率** | 命中的 gold 要点数 ÷ gold 要点总数 | gold 要点数 | 字面匹配器不理解同义改写 → 会低估（实测低估约 15-25pp） |
| **幻觉率** | 有问题的 evidence 条数 ÷ evidence 总条数 | evidence 条数 | 只检"能否回溯原文"，不检"是否切题" |

### 关键设计：证据必须可逐字回溯

evidence 规则（写在 System Prompt 里）：
> **evidence 必须是原文的完整连续子串**：与原文逐字一致的一整段话，不得删去中间内容、不得改写用词、不得拼接。

为什么拧到最严：
- 检查器只需要一个 `in` 判断（归一化后子串匹配），**测量简单**
- 可追溯性最强：每条结论都能在原文里精确框出来
- 代价是模型会多抄几个字 —— 可接受

曾经放宽到"允许删去中间若干字"，结果模型把整句删掉、检查器认不出 → 最后收紧。**教训：为了迁就检查器而放宽规则，方向反了。**

## 二、评测集构建规范

### 构成矩阵（照抄这个思路，L2/L3 按域调整）

| 维度 | L1 的取值 |
|---|---|
| 长度 | 短(<500字) / 中(500-2500) / 长(>2500) / 超长(>24000，触发截断) |
| 语言 | 中文 / 英文 / 中英混合 |
| 模板 | 全覆盖（L1 是 summary/todos/archive 三种） |
| 来源 | 真实来源 ≥3（注明 URL 与字数）+ 合成样本 |
| 特殊 | 含表格的文件、超长文本、负样本（如"没有任何待办的文章"） |

### 三条纪律

1. **构成写进构建脚本**（`scripts/build_evalset.py`），改样本改脚本重跑，不手改 JSON
2. **gold 标注是人工活，标完写状态**：`meta.gold_status = draft_manual + 日期`，等人工抽查后再改 `reviewed`。**不许假装已复核**
3. **行为类样本（测"系统行为"而非"内容要点"）要从覆盖率分母里排除**（L1 的 S19 超长截断）否则数字被污染

### 特殊样本要"真实"

含表格的样本必须走真实路径：生成 PDF → 真实提取 → 用**提取出来的文本**当输入（L1 实测：表格列会按文本块分行，这个"脏"形态本身就是测试点，比手焊的 Markdown 表格诚实）。

## 三、复算能力（最容易漏、最省钱）

**换指标定义后不要重跑模型**：
- 评测结果落盘时保存 `data`（结构化结果）+ `raw`（模型原始输出）
- 写 `rescore.py` 读同一份结果，用新匹配器/新指标定义复算
- L1 实测：一次复算把覆盖率从 67.1% 修正到 78.2%，**零 API 费用**

这条是评测体系能不能快速迭代的关键：模型调用是慢/贵的那一环，指标是快/便宜的一环。

## 四、失败分类框架（四类，不许混在一起）

| 类别 | 特征 | 处理 |
|---|---|---|
| **真 bug** | 换输入/换端点仍然复现 | 修代码或改提示词，修完回归 |
| **依赖故障** | 整批全失败、或换端点就好 | 探测端点可用性；不改产品逻辑，改默认顺序/加重试与兜底 |
| **测量工具问题** | 输出内容肉眼看是对的，指标却报错 | 修匹配器，用 rescore 复算，不重跑模型 |
| **策略问题** | 两种做法都能自圆其说 | 按目标用户显式决策，写进文档，让行为可预期 |

**为什么必须分类**：它决定你把时间花在改代码、改提示词、还是改退路说明上。看到数字不好就乱调提示词 = 白烧钱。

### 匹配器的坑（L1 踩过两次同类）

1. 中文逐字整串匹配 → 多一个"的"就判失败（12/13 被压成 7/13）
2. 结果侧只收中文二元组 → 英文样本覆盖率全为 0
3. 归一化去空格后按 `[A-Za-z]{3,}` 提英文词 → "API spec" 黏成 "apispec"，单词边界丢失

**结论**：匹配器要同时处理 ①中文二元组 ②从**原始文本**提英文词 ③数字硬约束（数字必须精确出现）。每条都要有回归测试。

## 五、评测报告的写法（怎么讲才可信）

1. **先写指标，再写口径**：数字后面必须跟"分母是什么、匹配器是什么、gold 什么状态"
2. **提升要归因拆解**：L1 覆盖率 67%→91%，拆成"测量修复 +11pp"和"提示词修复 +7pp"——**分得清哪些是数字变好看、哪些是产品真变好**
3. **失败要分类**，不要只报"未命中 N 条"
4. **不许替用户断言**：gold 没复核就说"待复核"，样本少就说"不构成结论"
