## 一、核心问题

产品经理简历最难的处境是：**你没有代码，没有销售额。**

那怎么在一页纸上证明"**你的判断值钱**"？

### 先看一段典型的失败写法

> "负责 XX 产品的需求调研、撰写 PRD 文档、跟进研发排期与上线。"

**这三句话大概率是真的**，问题在于——它换到任何一家公司、任何一个产品、任何一个产品经理身上都成立。

面试官看完只知道"你确实是个产品经理"，不知道**你做过什么、你的判断水平如何**。

### 五条核心原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **数字优先** | "负责 XX 需求调研" → "访谈 8 位用户，定位出 3 个痛点，其中 X 被验证为最高频" |
| 2 | **体现决策** | 写出"放弃了什么、为什么"——**面试官最想看的是决策过程，不是最终稿** |
| 3 | **划清边界** | 明确"我做了 X，Y 是现成的/别人做的"——含糊其辞会在深挖时崩 |
| 4 | **一页纸** | 应届生一律一页。删掉所有"负责/参与/协助"开头的无信息量句子 |
| 5 | **可验证** | 凡是写上去的，都要能被追问三层：怎么做的 → 数据是什么 → 你负责哪部分 |

## 二、项目经历的四段式写法

这是产品经理简历的核心方法。每一段经历（实习或项目）都按这四段写：

```
【背景】  什么问题、什么约束、为什么要做
【动作】  你具体做了什么（怎么调研、怎么取舍、怎么推动）
【结果】  量化结果（数字！）
【影响】  沉淀/复用/更大范围的效应
```

### 完整改前改后范例

**改前（无效）**
> 负责 XX 产品的需求调研、撰写 PRD 文档、跟进研发排期与上线。

**改后（有效）**
> **【背景】** XX 场景下用户流失率高，现有决策无数据支撑。
> **【动作】** 设计并执行 8 场用户访谈，用 JTBD 拆出 3 类核心任务，推动其中 1 个方案进入排期。
> **【结果】** 方案上线后该流程完成率从 **61% 提升至 78%**。
> **【影响】** 该访谈模板被团队复用为后续需求评估的标准动作。

### 你的第一个项目该这样写

```
【问题】发现研究生文献阅读效率低，现有工具无法做跨文献对比。
【研究】访谈 6 位同门，确认"对比"是最高频痛点（而非"摘要"）。
【取舍】放弃全文摘要功能，聚焦跨文献对比；对比过规则匹配方案，
        因用户问法开放且规则维护成本随时间上升，改用大模型。
【效果】建 40 条评测集，准确率从 62% 提升至 81%，失败集中在超长文档场景；
        15 位同门实际使用。
```

**这段为什么强**：
- 有**真实研究**（访谈 6 人，不是脑补）
- 有**取舍**（放弃摘要、对比规则方案）
- 有**为什么必须用 AI**（规则维护成本会爆炸）
- 有**实测数字和失败分析**（62%→81%，失败在哪）
- 有**真实用户**（15 人）

## 三、简历结构（应届生一页纸）

| 模块 | 占版面 | 要点 |
|---|---|---|
| 基本信息 | 1 行 | 姓名 / 电话 / 邮箱 / **GitHub** / **作品集链接** |
| 教育背景 | 2–3 行 | 学校、专业、学位、起止时间；GPA/排名（好才写） |
| 技能 | 3–4 行 | AI 工具链 / Python / SQL / Figma / 数据分析 |
| **实习经历** | **最多** | **倒序**；每条按四段式；★ 最重要的一栏 |
| **独立项目** | **次多** | ★ 你的差异化武器；每条按四段式（问题/研究/取舍/效果） |
| 校园经历/竞赛 | 少 | 只写有产出的，不写"参加过" |
| 自我评价 | **删除** | 对应届生无加分，空间留给项目 |

### 各栏写法示例

**教育背景**
```
北京印刷学院 · 电子信息（人工智能方向）· 硕士 · 2026.09 – 2029.06
```

**技能**（不要写"了解/熟悉"，要说能做什么）
```
· 熟练使用 Cursor、Claude Code 独立完成 AI 应用开发与调试
· Python 数据处理与脚本编写；能独立跑通 RAG / Agent 应用
· Figma 交互原型设计；SQL 数据查询；ProcessOn 业务流程图
· 熟悉 AB 实验设计、指标体系搭建、用户访谈方法（JTBD）
```

**作品集链接**
必须有。你把 myblog 的 `portfolio/` 板块放上去即可——**别人还要从零搭作品集站，你已经有了**。

## 四、针对 AI 产品经理的特别提醒

### 1. 不要堆砌 AI 词汇

一线反馈明确说：
> "简历里多写几个'AI'，或许能骗过机器筛选，但**面试时一定会露怯**。"

非技术岗不要求你懂模型原理，但**必须拿得出作品、能讲清每一步怎么做**。

### 2. 说清"用 AI"和"做 AI"的区别

> "用 AI 的也是 AI 岗，开发 AI 的也是 AI 岗，**这两件事在招聘里完全不是一个量级**。"

你在简历里要体现的是：**能独立把 AI 应用做出来**（这是你作为 AI 硕士的独有优势），而不只是"会用 AI 工具提效"。

### 3. 证书没用

> "**证书没什么用，真正有用的是作品和实习。**"

### 4. 双非不是死刑，关键在"垂直"

> "互联网大厂反而会在学历和经历之间权衡，**只要实习足够垂直，双非也可能进入下一轮**。"

**"垂直"的含义**：投 AI 产品岗，简历上就得有 **AI 产品**的经历。一段电商运营实习 ≠ 垂直。

### 5. 实习段落怎么写（拿到实习后）

| 别写 | 要写 |
|---|---|
| 参与 XX 功能设计 | 主导 XX 环节的方案设计，输出 X 份文档，推动 X 进入排期 |
| 跟进研发进度 | 协调 X 名研发，将原定 X 周的排期压缩到 X 周 |
| 分析用户数据 | 从 X 条数据中定位出问题集中在 X 环节，推动改版后该指标提升 X% |

## 五、简历打造时间线

简历不是一次性写成的，是**随项目长出来的**。

| 时间 | 做什么 |
|---|---|
| 第 1 周 | **建骨架文件**（一页纸，先把模块搭好，不填空话） |
| 第 2 周 | 填"教育背景"+"技能" |
| 第 3 周 | 开"独立项目"栏，写立项背景 |
| 第 4–7 周 | 随项目推进，逐条补：问题定义 → 竞品认知 → 方案取舍 → 产出物 |
| 第 9 周 | 补"技术实现"一行（体现你能独立做出来） |
| 第 11 周 | 补"迭代依据"（谁提的反馈、你改了什么） |
| **第 13 周** | **★ 补上实测数字**（关键一步，没这步简历只是及格） |
| 第 14 周 | **全文重写一遍**，删掉所有"负责/参与" |
| 第 15 周 | 找师兄/HR 帮看一版并收集意见 |
| 第 16 周 | **定稿** + 准备"简历外延问题"清单 |
| 第 17–18 周 | 按目标暑期实习 JD 微调；建投递台账 |

> **为什么第 14 周要重写**：写第一版时你在"记录"，第 13 周拿到实测数据后重写，才能从"记录"变成"推销"。

## 六、常见错误清单

写完简历后逐条自查：

- [ ] 有没有"**负责** XX 需求调研、**撰写** PRD 文档"这类换谁都成立的句子？→ 删掉重写
- [ ] 每条经历有没有**数字**？
- [ ] 有没有写出**放弃了什么、为什么**？
- [ ] 有没有含糊的"参与/协助"？→ 要么改成"主导了 X 环节"，要么删掉
- [ ] 能不能**划清边界**（哪些是我做的，哪些不是）？
- [ ] 是否**一页**？
- [ ] 有没有**作品集链接**？
- [ ] 有多少个"AI"是**装饰性的**（写了但讲不出细节）？→ 删掉
- [ ] 技能栏有没有写"了解/熟悉"这种无法验证的词？→ 改成"能做什么"
- [ ] "自我评价"栏删了吗？

## 七、投递前最后三问

投任何一家之前，问自己：

1. **我的简历里有几段"垂直"的 AI 产品经历？**
   → 0 段就先别投大厂，先去拿一段，别浪费机会。

2. **把简历里任意一条经历拿出来，我能不能讲 3 分钟并扛住 3 层追问？**
   → 不能的条目，要么补细节，要么删掉。

3. **这段经历换到另一个人身上，还成立吗？**
   → 成立 = 无效信息。
