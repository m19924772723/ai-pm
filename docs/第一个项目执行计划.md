## 0. 先说你买的俞军那本怎么用

**别从头读到尾。** 这本书的结构是五部分（产品经理是什么 / 企业-用户-产品的关系 / 交易模型 / 如何做决策 / 产品经理的选拔与成长）+ 附录认知迭代史。

本周只做两件事：
1. **精读第一部分「产品经理是什么」** —— 建立"这个岗位到底在干什么"的框架。
2. **背下并理解那个公式**：**用户价值 = 新体验 − 旧体验 − 替换成本**
   → 做项目时，这就是你判断"值不值得做"的第一把尺子。后面写 PRD、做取舍、答面试题都要用它。

**第 3 部分「交易模型」留到第 5 周做方案取舍时回看**（讲的是怎么算商业账）。第 5 部分和附录**现在不要看**，那是给准备晋升的人看的。

**只精读 1 个部分 + 1 个公式，本周完成。** 剩下的当工具书。

## 1. 规划原则：从面试问题倒推

整个项目是**倒着设计**的。先看面试官会问什么，再决定每个阶段要留下什么。

| 面试官会问 | 你需要提前造出什么 | 在哪个阶段造 |
|---|---|---|
| 这解决谁的什么问题？ | 真实用户访谈记录（不是脑补） | P1 |
| 为什么这么做？有没有别的方案？ | 被放弃的方案 + 放弃理由 | P2 |
| AI 到底是不是必要的？ | 对比过"非 AI 方案"的结论 | P2 |
| 效果怎么衡量？ | 定义好的成功指标 | P4 |
| 效果到底好不好？ | **实测数字**（评测集 + 得分） | P4 |
| 失败是怎么排查的？ | 失败案例记录 + 你改了什么 | P3 / P4 |
| 有没有上线？谁在用？ | 真实用户数（哪怕 10 个人） | P5 |
| 你自己负责了哪部分？ | 明确的"我做了 X，Y 是现成的"界线 | 全程 |

> **判断标准**：上面 8 个问题，如果每个都能拿出**证据**（文档、数据、截图），这个项目就成了。拿不出证据的那一格，就是你下一周要补的。

## 2. 选什么项目

### 三道硬筛选（三条必须全过）

1. **你自己或身边人是真实用户吗？**
   → 不是，就没法访谈、没法验证、没法拿到真实反馈。**直接淘汰。**
2. **4 周内能做出可运行的 MVP 吗？**
   → 做不到就太小众或太宏大。**砍到能做完。**
3. **能说清"为什么必须用 AI"吗？**
   → 答不上来就是"给传统功能硬套 AI"，面试时一问就穿。

### 三个候选（按推荐度）

| 候选 | 痛点真实性 | 与你的资源契合 | 4 周可做 | AI 必要性 | 推荐度 |
|---|---|---|---|---|---|
| **A. 印刷/包装品缺陷检测辅助工具** | 高（行业真实痛点） | **满分**——北印行业资源 + 你的小论文方向就是图像缺陷检测 | 中（需数据集） | 强（视觉模型） | ⭐⭐⭐ **一石二鸟** |
| **B. 论文/文献阅读与对比 Agent** | 高（你自己每天在痛） | 高（你就是用户，同门就是访谈对象） | 高（纯软件） | 强（长文本、结构化提取） | ⭐⭐⭐ **最稳** |
| **C. 课程 / 实习信息聚合助手** | 中 | 中 | 高 | **弱**（用爬虫就够，AI 是多余的） | ⭐ 淘汰 |

### 推荐

**首选 A，如果条件不成熟（导师方向不符 / 拿不到数据集）就立刻转 B。**

- **选 A 的理由**：项目 + 小论文 + 行业资源三者合一。**一次投入，同时喂饱"作品集"和"学术成果五选一"**。你是 2029 届，时间看似多，但小论文必须在研一下投出——把两件事合并是最高效的走法。
- **A 的风险**：依赖导师方向和数据集。**第 3 周就要确认**，别拖到第 6 周才发现做不了。
- **B 的价值**：不依赖任何外部条件，你 100% 能独立完成，且"研究生读论文"这个痛点你天天在经历——访谈、验证、迭代全都跑得通。

**C 类直接淘汰**：AI 不是必要的，做了也讲不出"为什么需要 AI"，面试时会很尴尬。

### 第 3 周必须做出的决定

- [ ] 找导师确认：方向和数据集能不能支持 A
- [ ] 能 → 做 A；不能 → 做 B，**当天就定，不再纠结**
- [ ] 写下选题理由（3 句话，留着面试用）

## 3. 五阶段流程（可复用）

这套流程不只用于第一个项目——**后面作品集的 3 个案例都用同一套**，练熟一次受益三次。

```
P0 选题定界  →  P1 用户研究  →  P2 方案取舍  →  P3 做出来  →  P4 度量  →  P5 复盘包装
  (1周)          (2周)           (3周)           (4周)        (2周)       (3周)
```

### P0 选题定界（第 3 周）

| 项 | 内容 |
|---|---|
| **做什么** | 用三道硬筛选选定项目；明确"不做什么"（范围边界） |
| **产出** | 一页纸：目标用户 / 核心问题 / 本版本做什么 / **明确不做**什么 |
| **技能** | `problem-statement`、`proto-persona` |
| **自检** | 我能一句话说清"给谁解决什么问题"吗？ |

### P1 用户研究（第 3–4 周）

| 项 | 内容 |
|---|---|
| **做什么** | 访谈 **5–8 个真实用户**，每人 20 分钟；问过去的行为，不问"你会不会用" |
| **产出** | 访谈记录 + 痛点排序 + JTBD 分析 |
| **技能** | `discovery-interview-prep`、`jobs-to-be-done` |
| **自检** | 我听到的痛点是**别人说的**，还是我**以为的**？ |

> ⚠️ 最常见的失败：跳过这一步，直接开始写代码。**没有 P1，你后面所有产出都是"我觉得"**，面试时一问就崩。

### P2 方案取舍（第 5–7 周）

| 项 | 内容 |
|---|---|
| **做什么** | 竞品分析 3 家 → 列 5–8 个候选功能 → **砍到 2–3 个** → 写 PRD → 画原型 |
| **产出** | 竞品矩阵 + **取舍记录（含被砍掉的方案和理由）** + PRD + Figma 原型 |
| **技能** | `competitive-research-snapshot`、`prioritization-advisor`、`prd-development`、`user-story` |
| **自检** | 我能不能说清"为什么不做 X"？——这是面试最容易加分的地方 |

> **必做的一件事**：明确写出"**为什么不用非 AI 方案**"。比如"用规则匹配也能做，但用户的实际问法是开放的/多样的，规则维护成本会随时间爆炸"。这句话直接回答面试官的"AI 是不是必要的"。

### P3 做出来（第 8–11 周）

| 项 | 内容 |
|---|---|
| **做什么** | 技术选型 → 搭 MVP → 让它能跑起来给真人用 |
| **产出** | 可运行的 demo + README（说清怎么跑、解决什么问题） |
| **技能** | `lean-ux-canvas`、`derisk-measurement-advisor` |
| **自检** | 一个陌生人拿到我的链接，能不能自己跑通？ |

**技术选型的三个提醒**
1. **用现成模型和框架**，不要自己训模型（除非 A 方案的小论文需要）。目标是"产品跑通"，不是"技术炫技"。
2. **每周 commit**，README 跟着写。面试官会看你的 GitHub。
3. **每遇到一个坑就记一行**（报错信息 + 你怎么解决的）——这就是"失败怎么排查"的答案来源。

**止损线**：第 11 周末如果核心功能还跑不通，**立刻砍范围**（砍到只留最核心的 1 个功能），不要延期，因为后面还有 P4/P5。

### P4 度量（第 12–13 周）

| 项 | 内容 |
|---|---|
| **做什么** | 定义成功指标 → 建评测集（20–50 条）→ 实测 → 找失败案例并改进 |
| **产出** | **实测数字**（准确率 / 耗时 / 成功率）+ 失败案例分析 + 改进前后对比 |
| **技能** | `derisk-measurement-advisor`、`pol-probe` |
| **自检** | 我的效果数字是**测出来的**还是**估出来的**？ |

> 这一步是**绝大多数学生作品的分水岭**。别人交"我做了个 Agent"，你交"我做了个 Agent，准确率从 62% 提到 81%，失败主要集中在 X 场景，原因是 Y，我改了 Z"。**后者才叫产品经理。**

### P5 复盘包装（第 14–16 周）

| 项 | 内容 |
|---|---|
| **做什么** | 作品集页上线 → 写讲法 → 模拟面试 |
| **产出** | myblog `portfolio/` 板块上线 + 3 分钟版 + 15 分钟版讲法 + **真实用户数** |
| **技能** | `product-sense-interview-answer`、`storyboard` |
| **自检** | 我能不看稿讲 15 分钟吗？被追问三次还稳得住吗？ |

**争取真实用户**：发给 10–20 个同门用，收集反馈。哪怕只有 10 个用户，"**有 10 个人在用**"也远胜"我自己测试过"。

## 5. 弹药清单（最终交付检查表）

项目结束时，这 8 份证据必须都在：

- [ ] **访谈记录**（5–8 人，含原话）→ 回答"解决谁的问题"
- [ ] **竞品矩阵**（3 家）→ 回答"市场认知"
- [ ] **取舍记录**（含被砍方案 + 理由）→ 回答"为什么这么做"
- [ ] **非 AI 方案对比**（为什么必须用 AI）→ 回答"AI 是否必要"
- [ ] **PRD + Figma 原型** → 回答"专业性"
- [ ] **可运行 demo + GitHub README** → 回答"能不能做出来"
- [ ] **实测数据 + 失败分析 + 改进前后** → 回答"效果和排查"
- [ ] **真实用户数 + 作品集页** → 回答"有没有人用"

**8 项齐了 = 第一个项目完成。**

## 6. 三条止损规则

1. **第 3 周没定下选题** → 直接做 B（文献阅读 Agent），不再讨论 A。
2. **第 11 周核心功能还跑不通** → 砍到只剩 1 个功能，保住 P4/P5。宁可小而完整，不要大而残缺。
3. **第 15 周还没上线** → 先把现有版本放上去（哪怕粗糙），用户反馈比完美更重要。

> 记住：**项目的价值不在于做得多大，而在于"每个结论都有证据"。** 一个只有 1 个功能但有真实用户和实测数据的小工具，比一个功能齐全但全是"我觉得"的大项目值钱得多。
