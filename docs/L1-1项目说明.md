# L1-1 项目说明：长文 → 结构化（一页版）

> 写完日期：2026-10-05（Day 13）　·　对应面试"能讲 15 分钟的项目"
> 原则：每个数字都能指向 logs/ 里的真实产物，不手写数字。

---

## 一句话

**贴一段长文、一个链接或一份 PDF，30 秒出结构化结果（摘要/关键点/标签/待办），每条要点都带原文逐字证据，可切模板、可导出 Markdown。**

## 解决谁的什么问题

学生/知识工作者读完长文要做笔记：一篇 5000 字文章手动整理约 30 分钟，要点散落难复用、待办容易漏。

## 为什么必须用 AI

1. **"按需提取重点"规则做不到**：同一篇文章，有人要方法、有人要结论、有人要数据，模板写死就失效。
2. **语义压缩不可规则化**：核心信息散布段落间，关键词提取只有高频词，得不到结论。
3. **输出形态随任务变**：同一输入，摘要/待办/归档要出完全不同的结构。

## 方案与取舍（面试重点）

| 决策 | 选择 | 为什么 |
|---|---|---|
| 界面 | Streamlit | Python 原生，2 周出可交互 demo，不用前后端分离 |
| 结构化输出 | 固定 JSON Schema + 三条 System 规则 | 可解析、可评测、可展示 |
| 证据约束 | **evidence = 原文完整连续子串**（逐字一致，不许改写/删改/拼接） | 每条结论可精确框回原文；宁可多抄不改写 |
| 字段完整性 | Schema 全字段必须出现，缺省填未指定 | 英文输出曾漏字段（S09），规则 6 修掉 |
| 语言 | 输出固定中文，术语保留原文 | 目标用户是中文知识工作者（S11 定案） |
| 输入降级 | URL 抓取失败/扫描 PDF → "请手动粘贴" | 2 周 MVP 不做 OCR，明确边界 |
| 明确不做 | 登录/云同步/批量/多轮对话 | 控制成本，聚焦核心链路 |

## 效果（真实评测数字，20 条评测集）

| 指标 | 数字 | 说明 |
|---|---|---|
| 格式合规率 | **95%**（19/20） | 唯一失败为端点故障（stepfun 长文不稳，deepseek 兜底通过） |
| 要点覆盖率 | **90.8%**（69/76） | 匹配器口径；提升归因：测量修复 +11pp、提示词修复 +7pp |
| 幻觉率 | **1.05%**（1/95） | 严格口径：一条证据跳句违规被如实抓出，无编造内容 |
| 超长输入 | ✅ | 4.2 万字正确截断 + 警告，不崩溃 |
| 单元测试 | 38 个 | 离线、不花 API 费用 |

**覆盖率的诚实口径**：gold 为 2026-10-01 标注草稿（draft_manual），待人工抽查复核；匹配器是字面近似，不理解同义改写。

## 踩坑（失败怎么排查的）

1. **JSON 解析失败 ≠ 模型不会写 JSON** → 看 finish_reason，根因是 4096 token 被推理吃掉 → 提到 8192 + 截断显式化
2. **覆盖率 15% 先怀疑产品** → 逐条对照发现是匹配器逐字匹配太严（多一个"的"就失败）→ 改二元组重叠，复算不重跑模型
3. **"evidence 找不到"先分类** → 改写/删节/跨句拼接三种弱引用，都不是幻觉 → 规则拧到最严
4. **全部调用失败** → 探测是 siyu 订阅失效（403），不是代码 → 换 stepfun 默认、deepseek 兜底
5. **英文样本覆盖率为 0** → 匹配器只收中文二元组 → 补英文词；又一个归一化丢单词边界的 bug → 从原始文本提取
