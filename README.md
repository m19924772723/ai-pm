## 🎯 两条主线

1. **一段垂直的 AI 产品实习** —— 简历上唯一被反复验证的硬通货
2. **一个能讲 15 分钟的项目** —— 拿到实习的入场券 + 面试全程的弹药

> 第 0 条前提：选一个**放实习**的导师。

---

## 🪜 项目阶梯（从低到高）

| 层级 | 项目 | 时间 | 进作品集 |
|---|---|---|---|
| L1 提示词级 | 长文 → 结构化（摘要/要点/标签/待办） | 第 3–4 周 | ✗ 练手 |
| L2 检索增强 | 个人知识库问答 / LLM Wiki | 第 5–8 周 | ✓ 案例① |
| L3 Agent 编排 | 深度研究 Agent / 浏览器 Agent | 第 9–12 周 | ✓ 案例② |
| L4 端到端 | 把 L2/L3 做成真产品 | 研一下 | ✓ 数据素材 |

**为什么这个顺序**：不跳级——L2 用 L1 的提示词与评测基础，L3 用 L2 的检索基础。

## 🔧 怎么用这个仓库

**每天**：在 `log/` 下新建当日文件（模板见 `log/README.md`），记计划 → 完成 → 踩坑 → 收获。
**每周日**：对照 8 个面试问题，检查哪一格还没有证据。
**改计划表**：改 `scripts/` 里的生成脚本后重跑，不要手改 Excel（保证与文档口径一致）。

## 📌 8 个必须能拿出证据的面试问题

| # | 面试官会问 | 证据在哪 |
|---|---|---|
| 1 | 这解决谁的什么问题？ | `log/` 里的访谈记录 |
| 2 | 为什么这么做？有别的方案吗？ | 取舍记录 |
| 3 | AI 是不是必要的？ | 非 AI 方案对比 |
| 4 | 效果怎么衡量？ | 指标定义 |
| 5 | 效果到底好不好？ | **实测数字** |
| 6 | 失败是怎么排查的？ | 踩坑日志 |
| 7 | 有没有上线？谁在用？ | 真实用户数 |
| 8 | 你自己负责了哪部分？ | 项目记录中的分工说明 |

> **8 个问题都能拿出证据 = 第一个项目成了。**
