# Metrics4（L2 四个检索指标跑齐）

**成果词**：Metrics4 —— L2 W3 排期目标"跑 4 个检索指标"达成，数字与目标对照成文

## 做成了什么

- `retrieval_eval.py` 升级：读 30 条正式评测集（20 有答案），新增**上下文相关性**指标
- 4 指标齐：召回率 90% / 上下文相关性 30% / 引用准确率 80% / 拒答正确率 100%
- `docs/L2指标汇总-W3.md`：指标关系、失败明细、口径、W4 优化清单
- 学习线精读 RAG 优化六大坑（6727 字）→ 映射出 W4 清单（Rerank 精排/查询改写）

## 为什么这件事重要

**4 个指标第一次全部有数字，且数字间讲出了一个完整故事**：
召回 90%（能找到）✅ → 上下文相关性 30%（筛不干净）❌ → 引用准确率 80%（被噪声拖累）❌

**"检索能找到，但捞上来一堆噪声"** 是 RAG 项目的典型中期形态——
面试讲这个比讲"我效果很好"更有说服力：我知道瓶颈在哪、下一步怎么修（Rerank）、
用什么指标验证（上下文相关性 30% → ≥60%）。

## 可复现

```bash
python -m scripts.retrieval_eval            # 召回/MRR/上下文相关性（8s）
python -m scripts.qa_eval --out logs/x.json  # 引用/拒答（10 分钟）
python -m pytest tests -q                    # 38 单测
```
