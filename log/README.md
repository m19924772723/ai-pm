# 过程记录（log/）

**每天一份**，文件名 `YYYY-MM-DD.md`。这是整个仓库最重要的部分——
面试时你讲不出细节，多半是因为当时没记。

## 为什么必须记

面试官的追问链是这样的：

> 你这个方案为什么这么设计？→ 失败了怎么排查？→ 不同方案的数据对比？→ 有没有上线、谁在用、你负责哪部分？

**答到第三层就崩**，是因为实验室项目/个人项目没有经历过上线后才有的问题。
而这份日志就是把这些细节留住——**踩坑日志就是"失败怎么排查"的弹药**。

## 每天记什么（15 分钟）

```markdown
# YYYY-MM-DD（周X）第 N 天 · WX 阶段

## 今日计划
- 项目线：
- 学习线：
- 面试线：

## 实际完成
- [ ] ...

## 踩坑日志
| 问题 | 怎么试的 | 结果 |
|---|---|---|
|  |  |  |

## 收获 / 面试素材
- （能写进简历或讲给面试官的一句话）

## 明日
-
```

## 三条记录纪律

1. **当天记**，不要攒到周末——细节会忘。
2. **踩坑日志写"怎么试的"**，不只是"报什么错"——面试官关心的是你的排查过程。
3. **每天至少留一句"面试素材"**——能直接写进简历或讲给面试官的话。

## 每周日额外做

对照仓库 README 里的 **8 个面试问题**，检查哪一格还没有证据 → 写进下周计划。
