## 踩坑日志

**1. 提示词模板里含 JSON 花括号，不能用 `str.format()`**
- 现象：`KeyError: '\n  "title"'`
- 怎么试的：先想加 `{{}}` 转义 → 太脆，模板里 Schema 很多行都得改；改成显式占位符 `replace()`
- 结果：占位符替换可用，并加了 2 个回归测试（模板花括号不被破坏、Schema 示例本身是合法 JSON）
- **面试可讲**：这就是"把提示词当代码管理"的最小事例——改完必须补测试

**2. siyu 的密钥订阅失效，是逐个探测才定位的**
- 现象：整轮评测 4 条全部 `HTTP 403 SUBSCRIPTION_NOT_FOUND`
- 怎么试的：写 `scripts_probe.py` 逐个 provider 打一次极短调用 → 发现 siyu 403、tuoji 503 无可用通道、deepseek 返回空、**stepfun 正常**
- 结果：把默认顺序改成 stepfun 优先；siyu 保留在列表里等恢复
- **面试可讲**：不要把"服务不可用"当成"我的代码错"。先做最小探测区分**依赖故障**和**自身 bug**，再改代码

**3. 要点覆盖率虚低，根因在匹配器不在模型**
- 现象：v1 逐字匹配只有 7/13（53.8%）
- 怎么试的：把模型原始输出和人工金标逐条对照 → 模型写"产品经理**的**核心能力"，金标写"产品经理核心能力"，**多一个"的"整串就判失败**
- 结果：改成二元组重叠 ≥0.6 且数字必须命中 → 同批输出重算 12/13（92.3%）；并写 `rescore.py` 支持不重跑模型就复算
- **面试可讲**：**指标本身也要被验证**。第一版指标给出 15% 覆盖率时，先怀疑测量工具，而不是先改产品

**4. 输出被截断，根因是推理模型的 token 预算**
- 现象：归档模板 JSON 断在半句，`raw` 只有 132 字
- 怎么试的：先怀疑 Schema 太复杂 → 看 `finish_reason` 和 usage，把 max_tokens 从 4096 提到 8192
- 结果：4/4 通过；并且把截断做成显式信号（`truncated` 字段 + 界面红字提示）
- **面试可讲**：失败要能归类。"JSON 解析失败"是表象，真因是"输出预算用尽"——产品上要给用户不同的提示和不同的解法

**5. 自己代码里的同类 bug**
- 现象：匹配器短路分支拿**原始**金标（带空格）去比**归一化**后的文本，永不命中
- 结果：改成两侧都归一化；补测试固化
