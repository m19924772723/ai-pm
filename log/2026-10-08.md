### 3. 分块策略（核心决策）
- **标题层级切段 + 超长段句子窗口**：512 字上限 / 64 重叠 / 40 下限
- 每块记录原始字符偏移 —— 引用能精确高亮到原文的前提
- 三条硬不变量全部有单测：块文本 == 原文切片、无块超限、正文不丢（只丢空白+短碎片）
- 踩坑：硬切重编号与已有 chunk_id 撞车（Chroma DirectIDError）→ 最后统一重编号
- 结果：501 块，最长恰 512，偏移自检 0 不符，相邻重叠 12%

### 4. 索引跑通

- Chroma 持久化 + manifest（指纹/参数/模型全记录）；--check 显示 in_sync=true

### 5. 检索质量诊断 → 混合检索（本日最大发现）
- **纯稠密检索不可用**：10 问 Recall@5 = **0/10**，Top1 是 ASCII 线框图
- 诊断三步：向量退化？→ 否（cos=1.0 确定性，无关文本 0.47 vs 相关 0.80）
  Chroma 召回 bug？→ 否（numpy 全量余弦结果一样）→ 根因：**embedding 模型对中文区分不足**
  501 块相关度全挤在 0.69~0.82；ASCII 框线块对任何查询都最相关
  中转站也只有 2 个 embedding：nemotron-3-embed-1b（弱）+ nv-embed-v1（EOL）
- **解法：混合检索 = 稠密 + 中文二元组 BM25 → RRF 融合**
  二元组设计让 ASCII 线框图一个 token 都产生不了（天然免疫污染）
- 结果：**Recall@5 = 90%（9/10），MRR = 0.518**（稠密对照 0%）
- 引用偏移端到端核验 3/3：命中块文本 == 原文切片
